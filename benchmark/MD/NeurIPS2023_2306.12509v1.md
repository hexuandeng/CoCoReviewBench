# Abstract

We view large language models (LLMs) as stochastic language layers in a network, where the learnable parameters are the natural language prompts at each layer. We stack two such layers, feeding the output of one layer to the next. We call the stacked architecture a Deep Language Network (DLN). We first show how to effectively perform prompt optimization for a 1-Layer language network (DLN-1). We then show how to train 2-layer DLNs (DLN-2), where two prompts must be learnt. We consider the output of the first layer as a latent variable to marginalize, and devise a variational inference algorithm for joint prompt training. A DLN-2 reaches higher performance than a single layer, sometimes comparable to few-shot GPT-4 even when each LLM in the network is smaller and less powerful. The DLN code is open source.<sup>1</sup>

# 1 Introduction

The size of large language models (LLMs) has grown significantly over the last few years, mainly because of emerging capabilities [6, 34], but at considerable technical and societal costs [51, 2, 4]. Recent efforts have focused either on learning smaller models matching the abilities of larger ones on some tasks using distillation [46, 38, 32, 15], or offloading part of the computation to other dedicated components [31, 25, 28, 21]. In the latter case, this is done through carefully crafted instructions to retrieve the necessary information from these additional modules [50, 44, 8, 56, 27]. Our work falls in the general research direction of building modular systems.

Particularly, we view LLMs as language layers in a Deep Language Network (DLN). The learnable parameters of each layer are the associated natural language prompts and the LLM at a given layer receives as input the output of the LLM at the previous layer, like in a traditional deep network. Each layer uses a template to organize the conditioning information into a string before calling the LLM (see Fig. 1). This layering induces a learnable decomposition of the task into a series of smaller sub-tasks, each of which is more easily solvable by an LLM. This shares similarities to recent works that chain LLM calls [44, 8, 56]. In this work, we move towards integrating learnable components in the pipeline rather than relying on handcrafted rules: each layer is associated with prompt (language) parameters that need to be learned in such a way that the performance of the final objective is maximized.

We first show how to perform prompt optimization in a shallow 1-layer language network (DLN-1) which parametrizes a distribution  $p_{\mathrm{LM}}(y|x,\pi)$ , with learnable prompt  $\pi$  (Fig. 1, left). Our prompt optimization techniques extend the Automatic Prompt Engineer procedure from Zhou et al. [60]. The rest of the paper is organized as follows. First, we provide an interpretation of LLMs as shallow networks, drawing a number of analogies with standard parametric and non-parametric models and explaining how best to train them. We show how they can be trained using a form of variational inference, then demonstrate their performance on a series of reasoning and language understanding tasks.

# 2 One-Layer Language Networks

A pre-trained LLM with frozen weights might be thought of as a complete function class indexed by prompts. The output  $y$  of an LLM for an input  $x$  can be modulated through a prompt  $\pi$  by feeding a combination of  $\pi$  and  $x$  to the LLM. Hence, from a low-level perspective, the function class of an LLM is defined by its architecture, i.e., its depth, number of heads, context size, etc., and training happens at the parameter level. It is data and compute intensive and should be done rarely. From a high-level perspective, the function class of an LLM is defined by the pre-trained model chosen (LLAMA [47], text-davinci-003, GPT-4, etc.), and training happens by fine-tuning the model or by choosing the prompt.

There are two ways of optimizing an LLM at the prompt level. The first one is prompt engineering, a parametric optimization, where the optimization space is independent of the size of the dataset. Because this optimization usually happens in discrete space, gradient-based techniques do not apply and most efforts rely on a combination of random or local search and human heuristics [24, 58]. The second one is in-context learning (ICL), a non-parametric optimization technique where the solution is a direct function of a subset of examples [6, 23]. This approach works well for few-shot learning but scaling it to larger datasets has both performance and computational issues. We shall now generalize previous work in discrete prompt optimization [60, 24] with the ultimate goal of learning a set of prompts in a language network.

# 2.1 Language Layers

We use language layer to refer to a (stochastic) computation that takes as input a string  $x$  and outputs a string  $y$ . This computation is modulated by another string,  $\pi$ , generally called a prompt or instruction [60]. The string transduction is performed by an operator LM, by feeding  $x$  and  $\pi$  as context and generating a continuation  $y$ . Templates describe the way  $x$  and  $\pi$  are combined prior to being fed to the LM operator. These are functions that accept strings as variables and output a string. We will denote such templates with this font T. A simple "forward" template F() is the concatenation, i.e.  $\mathsf{F}(x,\pi) = "\{\pi\}\{x\}"$ . We also explore more complex ones, examples of which can be seen in Fig. 1.

Given an input  $x$ , a prompt  $\pi$ , and a template  $\mathrm{F}()$ , a language layer defines a probability distribution  $p_{\mathrm{LM}}(y|\mathrm{F}(x,\pi))$  over output strings  $y$  as computed by the LM. In the next section, we describe a generic framework for optimizing the weights  $\pi$  for a language layer.

# 2.2 Prompt Optimization: Improved APE

Because the search for the best prompt happens over a discrete space, we will rely on a local search method, using an LLM to implement a distance measure between prompts. The procedure can be seen as an extension of Automatic Prompt Engineer (APE), recently proposed by Zhou et al. [60], and will serve as a stepping stone towards introducing our algorithm for training deep language networks. Our prompt optimization algorithm can be structured as follows:

1. Given the current prompt  $\pi$  and a current batch of examples  $\{x,y\}$ , generate  $N$  "local" candidates  $\pi^1, \ldots, \pi^N$  using a prompt proposal distribution;  
2. Score each candidate using a (potentially stochastic) scoring function  $s$ , then choose  $\pi = \arg \max_{\pi^n} s(\pi^n)$ .

Prompt Proposal Local search algorithms assume a distance measure between inputs to crawl the search space. In this setting, we rely on LLMs to generate local modifications to the prompts. Our prompt proposal distribution takes as conditioning information  $\mathsf{a} /$  the batch given as input to the layer,  $\mathsf{b} /$  its corresponding output  $\{x,y,\hat{y}\}$ , and  $\mathsf{c} /$  the current prompt  $\pi$ . The proposal distribution  $p_{\mathrm{LM}}(\pi^n |\mathsf{B}_{\pi}(\{x,y,\hat{y}\},\pi))$  wraps this information using a particular "backward" template  $\mathsf{B}_{\pi}$ , which can be found in App. C. This approach is similar to the instruction template used by Zhang et al. [58], with the exception that we also integrate information about the model's own predictions, which we found to empirically help performance given that the model tends to propose prompts that correct its own errors. We sample from the prompt proposal distribution to generate a set of  $N$  prompts. A particularly important aspect is ensuring the diversity of the candidate pool  $\pi^1,\dots ,\pi^N$ . We devise several strategies to improve the diversity and the usefulness of the candidate samples in Sec. 4.

# 3 Two-Layer Deep Language Networks (DLN-2)

The natural extension of DLN-1 is DLN-2, in which language layers are stacked, i.e. the output of the first language layer is the input to the second one. A 2-layer network induces a distribution over outputs of the form:

$$
p (y | x) = \sum_ {h} p _ {\mathrm {L M}} \left(y \mid \mathrm {F} _ {r} \left(h, x, \pi_ {1}\right)\right) p _ {\mathrm {L M}} \left(h \mid \mathrm {F} \left(x, \pi_ {0}\right)\right) \tag {2}
$$

where  $h$  is a latent variable that potentially makes it easier to explain the target  $y$ . The output layer is also conditioned on  $x$  through  $\mathbf{F}_r$ , forming a residual connection (Fig. 1). This formulation is reminiscent of past work using latent language representations to guide document summarization [29]. In our case, however, the encoding/decoding distributions are parameterized by natural language prompts  $\Pi = \{\pi_0, \pi_1\}$ , and we do not assume access to the LLM parameters.

While this architecture has more expressive power than a shallow language network, the prompt optimization problem becomes harder now that we have to jointly search over both  $\pi_0$  and  $\pi_{1}$ . Doing random search in this space is impractical [10] and manual tuning of the weights is also exponentially harder than with a single prompt. We turn to variational inference to address this issue.

The layerwise decomposition of our system allows us to leverage tools from approximate inference in probabilistic models to learn  $\Pi$ . In particular, we propose to use variational inference to learn  $\Pi$  [3, 19]. We posit an approximate posterior  $q(h)$  over the latent variable  $h$ , and bound the marginal log-likelihood of  $y$  given  $x$  by computing the ELBO:

$$
\log p (y | x) \geq \sum_ {h} q (h) \log \frac {p _ {\mathrm {L M}} \left(y \mid \mathbf {F} _ {r} (h , x , \pi_ {1})\right) p _ {\mathrm {L M}} \left(h \mid \mathbf {F} \left(x , \pi_ {0}\right)\right)}{q (h)}. \tag {3}
$$

This bounds allows us to decompose the search over  $\Pi$  as two independent searches over both  $\pi_0$  and  $\pi_1$  as we have:

$$
\pi_ {0} ^ {*} = \arg \max  _ {\pi_ {0}} \sum_ {x, y} \sum_ {h \in \mathcal {H} _ {x}} w _ {h} \log p (h | \mathbf {F} (x, \pi_ {0})) \tag {4}
$$

$$
\pi_ {1} ^ {*} = \arg \max  _ {\pi_ {1}} \sum_ {x, y} \sum_ {h \in \mathcal {H} _ {x}} w _ {h} \log p (y | \mathrm {F} (h, x, \pi_ {1})) . \tag {5}
$$

The search over  $\pi_1$  is identical to the prompt optimization described in Sec. 2, with the difference that the inputs are now the samples from the approximate posterior rather than the inputs  $x$ . The search over  $\pi_0$  uses a similar strategy but uses the posterior samples  $h$  as targets, instead of the true target  $y$ .

However, that bound is only useful if it is close to the true value. Since its looseness is the KL divergence between  $q(h)$  and the true posterior,  $\mathrm{KL}(q(h)||p(h|y,x))$ : we need to find an approximate posterior  $q$  closely matching the true posterior. This search will rely on two tools: hidden proposal and posterior sharpening.

Hidden Proposal To maximize Eq. 3, we use an approximate posterior  $q(h)$  over the latent variables  $h$ . Because  $h$  is a string, we will also be using an LLM to sample  $h$ . Therefore, we parameterize  $q(h)$  with the same LM operator used in our language layers<sup>2</sup>. The hidden proposal distribution can condition on an increasing amount of information. If it conditions on  $\hat{h}$  itself, then  $q(h) = p_{\mathrm{LM}}(h|\mathsf{B}_h(\hat{h},y,\pi_1))$ , where  $\hat{h}$  is the output of the first language layer obtained with the previous value of the parameters  $\pi_0$ , i.e.  $\hat{h} \sim p_{\mathrm{LM}}(h|\mathsf{F}(x,\pi_0))$ .  $\mathsf{B}_h$  is a specifically tailored hidden proposal template, detailed in App. C. In this case, we can see the posterior proposal as a sort of hidden rewrite operation, where the LM is tasked to rewrite the hidden variable  $\hat{h}$  given some extra knowledge of the ground-truth label  $y$  and of  $\pi_1$ . In the case where  $q(h) = p_{\mathrm{LM}}(h|\mathsf{F}(x,\pi_0))$ , then we are fixing the approximate posterior to be equal to the prior. Jointly with the posterior sharpening introduced next,  $\pi_0$  will be trained to maximize the likelihood of the best samples from the previous prior distribution.

Posterior Sharpening Even as  $p_{\mathrm{LM}}$  is conditioning on potentially relevant information, the induced approximate posterior distribution is still far from the true posterior. To bridge that gap, we reweigh each sample  $h^i$  based on its probability under the true posterior distribution. More precisely, we compute  $\tilde{w}^i = \log p_{\mathrm{LM}}(y|\mathsf{F}_r(h^i,x,\pi_1)) + \log p_{\mathrm{LM}}(h^i|\mathsf{F}(x,\pi_0))$ , then assign to each  $h_i$  the probability  $w_i = \exp (\alpha \tilde{w}_i) / \sum_j\exp (\alpha \tilde{w}_j)$ , where  $\alpha$  is a tunable temperature parameter that controls the entropy of the posterior importance weights.

# 4 Practical Instantiation

Proposal Diversity To ensure a diversity of the samples for both the prompt proposal distribution and the hidden proposal distribution, we found helpful to use two strategies. The first is to modify the backward templates  $\mathsf{B}_{\pi}$  and  $\mathsf{B}_h$  before drawing a sample from the proposal distributions  $p_{\mathrm{LM}}(\pi)$  and  $p_{\mathrm{LM}}(h)$ . To achieve so, we parametrize the basic templates with a “ $\{\text{message}\}$ ” variable that we instantiate from a pool of hand-written instructions, that describe different behaviors the model should follow to propose new  $\pi$  and  $h$ . These can be interpreted as meta-instructions, i.e. high-level directives that inform the model on how to create a better instruction for the task, and extend instruction-induction templates used in [14, 58]. These can be found in App. C. In the future, we could envision to learn these instructions. In the case of  $\mathsf{B}_{\pi}$ , they could function as parameters for a prior over the weights of the DLN. For  $\mathsf{B}_h$ , they could serve as parameters that provide adaptivity to the approximate posterior thus tightening the ELBO. The second strategy to ensure more diversity is that we instantiate  $\mathsf{B}_{\pi}$  with a different random subset of examples in the current batch, before drawing each sample  $\pi^n$ . This effectively modifies the generation context for each sample  $\pi^n$ .

Backtracking and Memory Optimization of both DLN-1 and DLN-2 presents some heavy challenges due to the fact that we do not have gradient information and we sample a restricted set of candidates  $\pi^n$  at each optimization step due to computational reasons. We deploy multiple strategies to allow the network to be robust to sampling/selection errors. First, we include the current prompt  $\pi$  into the set of candidate prompts to be scored at the current iteration  $\pi^n$ . This allows the model to not take the step if the previous prompt performed better. Second, we keep a memory of  $M = 2$  best prompts found by tracking validation set performance.

Exploration Reward When training a DLN-2, we empirically observed that the first layer prompt  $\pi_0$  was updating very slowly. One hypothesis is that, due to the conditioning of the approximate posterior  $p_{\mathrm{LM}}(h|\mathsf{B}_h(\hat{h},y,\pi_1))$  on the hidden states  $\hat{h}$  obtained from the forward pass, the sampled hidden states  $h^i$  are close to  $\hat{h}$  and the maximizer of Eq.(4) remains  $\pi_0$ . To address this issue, we add to the scores of the candidate prompts an exploration reward that is proportional to the negative log-probability of the "incorrect"  $\hat{h}$ , i.e. those that led to the DLN making errors:  $r = -\lambda \log p_{\mathrm{LM}}(\hat{h} |\mathsf{F}(x,\pi^n))$  if  $\hat{y}\neq y$ . This encourages the model to both find prompts that maximize the log-probability of the posterior samples and at the same time minimize the log-probability of samples that led to incorrect predictions. We anneal  $\lambda$  to 0 during training with a constant schedule and we select the initial  $\lambda$  by monitoring validation performance for each task.

Training For DLNs, we use a batch size of 20 and train for 20 iterations by early-stopping on validation performance evaluated every 2 iterations. We then report test scores. We sample  $N = 20$  prompt proposals and  $K = 5$  hidden samples.

# 5 Experiments and Results

We design and conduct a set of experiments to help answer two main research questions: Q1: Can we outperform APE and In-Context Learning (ICL) with a DLN-1? Q2: Does network depth provide further improvement upon DLN-1?

# 5.1 Experimental Setup

Datasets and Tasks We adopt a set of eight NLP and reasoning tasks commonly used in prior work studying zero- or few-shot learning capabilities of LLMs [26, 12, 42, 45, 1]. We focus on classification tasks. For tasks adopted from BigBench-Hard (BBH) [45] (Hyper., Nav. and Logic.  $7^{3}$ ), we use the 250 data points provided by BBH as test set. We take the remaining data points from BigBench [42] that were not included in BBH, and randomly split them (evenly) into training and validation sets. For tasks adopted from [26] (Mpqa, Trec, and Subj), we randomly sample 400 and 250 data points from their training and test sets, respectively. We use the original validation sets. For tasks adopted from Leopard [1] (Disaster and Airline), we randomly sample 400, 250, and 250 data points as training, valid, and test. We list all tasks and their statistics in Table 3 in the Appendix.

We use accuracy as the evaluation metric. Specifically, given an input, we compare a system's output string against the ground-truth output string provided by the dataset. We score 1 if the two strings are identical and 0 otherwise. Before the comparison, we process the strings from both the model output and the ground-truth to deal with issues like tokenization and capitalization. In all our DLN experiments, we perform a hyperparameter search and run the same hyperparameter setting with three random seeds. We report the test accuracy averaged over three seeds corresponding to the hyperparameter setting that achieves the highest average validation accuracy. We report details of the hyperparameter search in the App. H.

Throughout this paper, we use OpenAI's GPT-3 model, specifically DaVinci-003, as the backbone to our proposed systems unless otherwise specified.

Baseline Systems We compare the DLN against two classes of baseline systems. First, we test a set of systems equipped with the same backbone (i.e., DaVinci-003):

- 0-shot: Given an input, the LLM is required to generate the answer in a zero-shot manner.  
- CoT [50]: Given an input, the LLM is first queried to generate a reasoning path with the prompt "Let's think step by step". Then, conditioned on the input and its first output, the LLM is queried to generate an answer. This is the zero-shot version of CoT.  
- ICL: Given an input as well as five data points as in-context examples, the LLM is queried to generate an answer. The five examples are randomly sampled from the training set.  
- KATE [23]: Given an input, we retrieve the five most similar data points from the training set using an off-the-shelf sentence encoder, and use them as in-context examples.  
- APE [60]: The LLM is queried to generate a pool of candidate prompts for the task given few input-output pair examples. The candidate prompts are evaluated on a validation set to find the best performing instruction prompt. The best instruction is then used for 0-shot evaluation. We optimize the prompt over both 15 and 400 examples (APE-15 and APE-400 respectively).

Additionally, we compare against one of the most advanced LLMs to date, GPT-4. We test 0-shot and ICL settings with GPT-4.

# 6 Related Work

Prompt-Based Machine Learning GPT-3 [6] demonstrated that sufficiently trained, sufficiently large language models are few-shot learners. This launched a new paradigm in NLP called in-context learning (ICL), or simply prompting. Research and tinkering have now extended it beyond traditional NLP tasks [24]. Liu et al. [24] provide an excellent survey of how prompting has developed in the last several years—a development that DLNs rely on and extend.

Despite the success of prompting, challenges remain. For instance, small changes to a prompt can have significant downstream impacts [31]—which has given rise to the packed field of prompt engineering [24]. Liu et al. [23] likewise showed that LLM performance can depend heavily on the choice of examples included in the prompt as in-context demonstrations: constructing the prompt with samples that are semantically similar to the test example helps significantly. This approach has since been key to several works [37, 43, 21].

The discovery of chain-of-thought prompts (CoT) marked a major advance in prompting: LLM performance improves markedly when the prompt includes examples of intermediate reasoning steps [50] (few-shot CoT), or simply instructs the model to "think step by step" [20] (zero-shot CoT). Like CoT, DLNs break a problem down into intermediate steps; however, they operationalize these steps as separate LLM calls, each defined by its own learned prompt. Since the introduction of CoT, prompting techniques have evolved to be more dynamic and iterative. Recent methods often operate recursively, with the prompt to an LLM containing LLM-generated text from a previous model call.

RECITE [44] is a CoT-based method that decomposes question-answering into two steps: reciting the relevant knowledge stored in model parameters, then generating the answer. In Self-ask [36], a model is prompted to ask and answer follow-up questions before answering an input question. Creswell et al. [8] decompose the question-answering problem into two interleaved steps: selecting supporting evidence from an LLM and then inferring an answer from an LLM that uses that evidence. Similarly, Zhou et al. [59] decompose questions into a sequence of sub-questions then answer each of them in turn, via sequential calls to an LLM, and Khot et al. [17] induce an LLM to generate a basic 'control flow' that calls distinct LLM modules. Yoran et al. [57] generate multiple independent chains of reasoning for a question, then process them using a meta-reasoner and predict the answer. And ReAct [56] generates reasoning traces and task-specific actions from LLMs operating in an interleaved manner. It achieves strong performance on multi-hop question answering and interactive decision making benchmarks.

A related class of methods uses 'self-talk,' where an LLM is prompted to ingest, evaluate, then possibly act on its own previous output. It is a precursor to DLNs, although without our layer-based conceptual framework nor our learning formulation. Self-critique [39], prompts LLMs to find flaws in previous LLM generations, then integrate the critique as feedback and refine the generation accordingly. Shinn et al. [41] propose Reflexion, which pairs ReAct [56] with this kind of self-reflection/critique and a memory module to help an agent improve its performance over several trials. Kim et al. [18] propose a prompting scheme whereby an agent recursively criticizes and improves its output to solve computer tasks. In Self-refine [27], an LLM generates an output, then the same model is prompted to provide multi-aspect feedback on its output; finally, the model refines its

previous output given its feedback. For improved planning in robotic control scenarios, Huang et al. [16] enable LLMs to conduct an inner monologue that leverages environment feedback and other inputs. Hao et al. [13] propose Reasoning as Planning, which repurposes an LLM as both a world model and a reasoning agent. Their method incorporates a planning algorithm based on Monte Carlo Tree Search to effectively explore the reasoning space. Coincident with our work, Du et al. [11] present a "society of minds" approach, whereby multiple language model instances propose and debate individual reasoning processes iteratively to arrive at a final answer. And simultaneously, Yao et al. [55] propose Tree of Thoughts (ToT), an extension of CoT that enables LLMs to make more deliberate decisions through self-evaluation, look ahead, and backtracking over multiple proposed reasoning paths. Generally, these methods do not use an explicit optimization procedure as DLNs do. On the other hand, Welleck et al. [52] propose a Self-Correct method that adds a trainable, possibly smaller corrector module on top of a base LLM—and explains that multiple correctors can be stacked. Distinct from DLNs, the corrector is trained by gradient descent on its parameters, to which the authors assume full access.

Augmented LLMs A related set of work focuses on prompting LLMs to use external tools—e.g., by generating code for API calls and conditioning on the returned text. These methods also tend to use repeated calls to a model with a growing or dynamic prompt that incorporates API returns. Consider MindsEye [25], which enables physical reasoning in LLMs by calling the MuJoCo engine to simulate scenarios described in text, then translating the simulation results back into text for a prompt. Another example of augmentation adds the ability to query search engines, as in Self-ask [36]. And most recently, Cai et al. [7] proposed a method by which LLMs can construct their own tools, implemented as Python utility functions, for a given task. That method operates somewhat like 1-layer prompt optimization in DLNs, but with a different output. Mialon et al. [28] provides a thorough survey of tool-augmented LLMs.

Prompt Optimization Techniques based on notions of self-talk and self-evaluation align naturally with automatic prompt optimization—a core function in DLNs. Early work in this category includes Autoprompt [40], which performs a gradient-based search for 'trigger' tokens, which coax a masked language model to perform some task like sentiment classification; and GRIPS [35], which splits instruction prompts into phrases, then uses a set of phrase-level operations (e.g., delete, swap, paraphrase, add) to optimize the instruction. Deng et al. [9] argue that 'enumeration-then-selection' heuristics for optimizing discrete prompts do not explore the prompt space systematically. They take an RL approach to overcome this problem, training a policy network, via soft Q-learning with a suitably designed and stabilized reward function, to generate effective prompts. In-context policy iteration [5] offers another RL-based approach to prompt learning. The method iteratively updates the contents of a prompt—which defines the policy of an LLM-based agent—through trial-and-error interaction with an environment. Most relevant to DLNs, Zhou et al. [60] present Automatic prompt engineer (APE). APE optimizes an initial prompt by searching over a pool of candidates to maximize a score function. APE demonstrates that an LLM can be used both to generate prompt candidates and to score them—i.e., according to the log probability of a groundtruth output under the LLM given the prompt candidate. We use an APE-inspired approach in DLNs and we cast the proposal/scoring functions as elements of variational inference. In [54], an initial set of instructions is rewritten automatically, step by step, into more complex instructions. This recalls prompt optimization across layers in DLNs, but the goal in [54] is to generate improved instruction data for fine-tuning a single LLM. Finally, we note an alternative to finding human readable prompts: optimizing continuous prompts [24], a.k.a. soft prompts. These are out of scope for us, since we assume no access to LLM internals.

Multi-Layer LLM systems Several recent works compose LLMs as nodes in a computational graph, which is the core idea of DLNs. Some work cited above can be seen as instances of this idea. For example, selection-inference [8] operates like a graph in which selection LLM nodes feed into inference LLM nodes to compose a single reasoning step, and multiple reasoning steps can be chained together. Similarly, Khot et al. [17] induce an LLM to generate a basic "control flow" that calls distinct LLM modules. Wu et al. [53] propose AI chains, an interactive system of chained LLMs based on a set of "LLM primitive" operations. They conduct a 20-person user study in which participants modify chains, and find this process to improve task performance, transparency, and controllability. Although our work on DLNs is also limited to linear networks (i.e., chains), we learn to modify their component operations. Dohan et al. [10] unify LLMs and graphical models as "language model

cascades". Specifically, they cast LLM compositions as graphical models with string-valued random variables. They show how scratchpad [33], chain-of-thought [50], tool use [28], and several other prompting strategies fit their formalism. DLNs can likewise be considered an instance of language model cascade, because of that framework's generality. However, going beyond the conceptual work of Dohan et al. [10], we present an effective technique for doing inference in an LLM-based graphical model and we apply learned networks of LLMs to several downstream tasks.

# 7 Conclusion and Future Work

At a moment where new techniques to engineer prompts abound, we believe DLNs could serve as an effective framework to systematically characterize these techniques and identify new opportunities for prompt optimization. Indeed, many prompt tuning techniques could be considered as a special instance of DLNs. We demonstrated how CoT can be seen as a DLN-2 with a residual connection. Generated Knowledge Prompting [22] could be considered as a fixed forward-only DLN-2 where, in the first layer, an LLM generates related knowledge, and in the second layer, another LLM takes the generated knowledge as input and generates the final answer. Prompting techniques like ReAct [56], Reflexicon [41], and Self-Consistency [48] could all be ensembles of DLN-1s with different prompt initializations. Our hope is that the DLN framework could inspire new prompt learning techniques by considering networks with different widths, depths, and connections.

Although we only tested 1-layer and 2-layer language networks so far, we already show that the performance of smaller LLMs can be boosted when stacked and prompted properly. Not only can we hope to eventually match the performance of the largest LLMs without incurring the large computational and data cost of training them, we believe the modularity of these architectures will make them more adaptable and reusable to new use cases. While accuracy on set tasks is an appealing metric, we argue that other considerations are just as important, for example the ease of adapting a model to one's own use case, or the ability to leverage multiple existing models.

Our work is far from finished and many interesting future directions are now open. First, we stick to using DaVinci-003 and testing with other LMs (or combinations thereof!) is needed. We noticed that DaVinci-003 has a tendency to always produce an answer given an example: this could be due to the particular 0-shot fine-tuning procedure, which biases the model towards generating useful responses. This raises the question of whether we can fine-tune "stackable" LLMs and whether DLNs can be used as a framework to generate training data for that purpose. Second, we engineered our backward and forward templates; in the future, we wish to expand our work to learn parts of such templates: we expect this to make the variational bound tighter and thus easing DLN's optimization. Additionally, while we only proposed 2-layer DLNs, the framework accommodates arbitrary directed acyclic graphs. Even with the current architecture, we assumed here we did not have access to the weights of each LLM. By lifting that restriction, we could fine-tune the LLMs at each layer as well as the ones used to approximate the posterior over the hidden variables. As distillation allowed smaller models to match the performance of much larger ones on specific tasks, we have reasons to believe that such fine-tuning could drastically improve the performance of the full system.

Impact statement While we are fully aware of the limitations of addressing societal issues through technical work, we hope that modular approaches like ours will alleviate some of the issues associated with LLMs, like the concentration of power associated with the difficulty to train them. We also hope that, by facilitating the reusability and adaptivity of such models, we shall make them more amenable to a wider variety of use cases. However, while we discuss the performance of these models on artificial benchmarks, we do not address the question of when and how such models should be deployed, nor do we offer additional guarantees against their misuse. We also emphasize that performance on artificial tasks, even if realistic, is neither representative of performance in uncontrolled environments, nor enough to justify the deployment of these models in high stakes situations.
