# ABSTRACT

Mobile UI understanding is important for enabling various interaction tasks such as UI automation and accessibility. Previous mobile UI modeling often depends on the view hierarchy information of a screen, which directly provides the structural data of the UI, with the hope to bypass challenging tasks of visual modeling from screen pixels. However, view hierarchy is not always available, and is often corrupted with missing object descriptions or misaligned bounding box positions. As a result, although using view hierarchy offers some short-term gains, it may ultimately hinder the applicability and performance of the model. In this paper, we propose Spotlight, a vision-only approach for mobile UI understanding. Specifically, we enhance a vision-language model that only takes the screenshot of the UI and a region of interest on the screen—the focus—as the input. This general architecture is easily scalable and capable of performing a range of UI modeling tasks. Our experiments show that our model obtains SoTA results on several representative UI tasks and outperforms previous methods that use both screenshots and view hierarchies as input. Furthermore, we explore the multi-task learning and few-shot prompting capacity of the proposed models, demonstrating promising results in the multi-task learning direction.

# 1 INTRODUCTION

Computational understanding of mobile user interfaces (UI) is a crucial step for achieving intelligent UI behaviors such as UI automation, and addressing interaction scenarios such as accessibility. Recently, mobile UI understanding has attracted numerous research interests. Previous works have proposed various UI modeling tasks and datasets, including widget captioning (Li et al., 2020c), screen summarization (Wang et al., 2021), command grounding (Li et al., 2020a; Bai et al., 2021; Burns et al., 2022) and other tasks (Li et al., 2022; He et al., 2020) on the mobile screen. Many of these works focus on bridging natural language and graphical user interfaces, which have shown the potential for enabling language-based interaction.

A mobile UI screen can come with a view hierarchy—a structural representation of the screen—in addition to the screenshot image. Using view hierarchy as input allows a model to directly acquire detailed information of UI objects such as their types, text content and positions on the screen, bypassing challenging visual modeling tasks such as inferring object information from screenshots (Li et al., 2021; Zhang et al., 2021). Previous works have shown the benefit of using view hierarchy in UI modeling in several tasks. For example, models using view hierarchy have achieved better performance than the vision-only variants in UI captioning tasks (Li et al., 2020c; Wang et al., 2021).

However, recent work has revealed that mobile UI view hierarchies constantly have inaccurate information about the UI screen, e.g., missing object text (Ross et al., 2018; 2017) and misaligned bounding boxes (Li et al., 2022). Such inaccurate information in the input can seriously hinder models in realizing their full potential in UI modeling. Although recent work has proposed methods for repairing view hierarchies (Li et al., 2022), substantial effort is still needed to robustly denoise raw view hierarchies. On top of these, UI screen data does not always have view hierarchies available in them, such as mobile UI images crawled from the web. Fetching view hierarchy at runtime in a mobile environment also imposes additional system constraints for the applicability of models that rely on view hierarchies.

In this paper, we investigate the direction of visual-only input by using UI screenshots, without using view hierarchies as input, for UI modeling tasks. We observe that many UI modeling tasks essentially aim to learn a mapping between the UI objects and text. As a result, vision-language models, a class of models that encode visual (and language) modalities and decode text answers, become a natural choice for the model architecture. Although previous works show that vision-only models generally perform worse than the models using both visual and view hierarchy input (Li et al., 2020c; Wang et al., 2021), we believe that visual language models offer two unique opportunities: 1) the simple architecture enables a model easily scalable, and 2) many heterogeneous tasks can be universally represented by the two core modalities of vision and language. These advantages have been evidenced by the recent successes of the vision-language models (Chen et al., 2022; Alayrac et al., 2022; Yu et al., 2022; Wang et al., 2022).

In contrast to previous visual-language tasks in the general domain, which usually use an entire image as input, UI modeling tasks are often concerned with a specific object or area on the screen. This requires a vision-language model to be able to focus on the object or area of interest. Thus, we propose Spotlight<sup>1</sup>, which enhances a vision-language model to generate text responses with respect to a focus object or region to support various UI modeling tasks (see Figure 1). In our experiments, we initialize Spotlight by leveraging pretrained large ViT (Dosovitskiy et al., 2021) and T5 (Raffel et al., 2019) checkpoints. We then pretrain Spotlight with an unlabeled dataset consisting of about 2.5 million mobile UI screens, which is followed by one of the three modeling strategies: single-task finetuning, multi-task finetuning or few-shot learning.

Our main contributions are three-fold. First, we propose a novel vision-language model architecture that is capable of finetuning, multi-task learning and few-shot learning for mobile UI tasks. The model can easily scale and generalize to other tasks without architectural changes. The model advances the art of pixel-only UI understanding and avoids the need to use view hierarchies as input that has many drawbacks in practice. Secondly, we develop a method for creating a large-scale pretraining dataset from automatically collected mobile screens. This pretraining dataset is crucial for the vision-language model to learn the prior knowledge of the unique domain of mobile screens. Finally, we conduct extensive experiments over the proposed model, including focus region representations and modeling strategies. Our experiments show that the proposed models obtain new SoTA performance in both single-task and multi-task finetuning for the three tasks, including widget captioning, screen summarization and command grounding. We also examine the feasibility of the proposed model for few-shot prompting.

# 2 RELATED WORK

UI modeling problems have drawn widespread interest from researchers in both the ML and HCI fields (Li et al., 2020c; Wang et al., 2021; Li et al., 2020a; Burns et al., 2022; Bai et al., 2021; Zhang et al., 2021; Wu et al., 2021; He et al., 2020). With the overarching goal of enabling intelligent UIs and addressing mobile accessibility, previous works have proposed a rich set of mobile UI modeling tasks, including tasks, datasets and benchmarks. Widget captioning (Li et al., 2020c) aims to generate natural language description for UI objects on the screen, which can be used accessibility features such as the TalkBack $^{2}$  screen reader to improve user experience for vision-impaired users. Screen2Words expands UI captioning by proposing the task for summarizing the entire screen (Wang et al., 2021). Command grounding maps a natural language command to a UI object on the screen, via single-step or multi-step interactions (Li et al., 2020a; Burns et al., 2022; Bai et al., 2021). These previous works used both the screenshot and the view hierarchy of a screen as input in their models, and revealed that multimodal input improve the performance over vision-only variants (Li et al., 2020c; Wang et al., 2021). Prior works have also borrowed language modeling techniques such as BERT (Devlin et al., 2019) for representation learning to facilitate downstream tasks (Bai et al., 2021; He et al., 2020). Recently, Li et al. (2021) investigated the feasibility of multi-task modeling for achieving a range of UI tasks simultaneously. To combat the lack of accurate view hierarchy, prior works have investigated model-based approaches for repairing noisy view hierarchies (Li et al., 2022), or UI object detection over screenshots to derive information such as object attributes and structure information (Zhang et al., 2021; Wu et al., 2021). Many of these mobile UI tasks are concerned with specific objects or areas on the UI screen. These models exploited large unlabeled data crawled from Web and demonstrate impressive finetuning and few-shot learning capacities. Vision-language models that encode images and decode text have leveraged the large pretrained vision and language components and observed significant performance gain, e.g., Flamingo (Alayrac et al., 2022) and PaLI (Chen et al., 2022). Specifically, Flamingo showed that the few-shot prompting ability of the large language model can generalize to multimodal cases using multiple pairs of image and text as input. We adapt this model architecture to explore few-shot and multi-task learning for mobile UI tasks, along with finetuning.

# 3 DATA

To introduce the problem space, we elaborate on the UI modeling tasks that we address and discuss the datasets we use for our investigation.

# 3.1 PRETRAINING DATASET

We use a large-scale dataset that consists of 2.69 million mobile UI screenshots with paired view hierarchies. The dataset was collected internally by crawling various mobile apps. As mentioned in Introduction (Section 1), many of the UI tasks are learning a mapping between a UI object and a natural language description, we propose to pretrain the models to decode text-based attributes of individual objects in view hierarchies, with only the screenshot image as the input.

Similar to previous work (Li et al., 2020c), we only use leaf objects as they are more likely to represent a functionality of the UI. For each object, we use three text-based attributes from a view hierarchy node: text, content description, and resource id. These attributes are showed to be important features for the models using view hierarchy as inputs (Li et al., 2020c; Wang et al., 2021). Note that we derive the output labels from view hierarchies but not use view hierarchy information as input.

To compensate for the missing text in view hierarchies, we further run OCR on the screenshot to extract additional text that might be present on the screen. Recognized single-line text with  $80\%$  or higher confidence are used. To improve the data quality, we preprocess the dataset to remove URLs, Unicode, single-character and non-alphabetical strings. We also remove text that rarely occurs, i.e., fewer than 5 times, or consists of common or generic phrases (e.g., "text view") that do not convey useful information about the object. In our pretraining, we randomly sample one out of the four text properties as the corresponding text label of a target object. Table 1 summarizes the statistics of the pretraining dataset.

# 3.2 UI TASK DATASETS

From various UI modeling tasks, we select three representative tasks to evaluate our models (see Figure 1). They are listed below.

- Widget Captioning (Li et al., 2020c): given an object on the screen, predict a natural language description for its functionalities.  
- Screen Summarization (Wang et al., 2021): given a mobile UI screen, predict a high-level summary for its contents and functionalities.  
- Command Grounding (Li et al., 2021): given a natural language command, find the UI object on the screen that matches the intent of the command.

These three tasks require models to learn the mapping between an UI object and a natural language description or command in both directions, i.e., object  $\rightarrow$  language and language  $\rightarrow$  object.

Furthermore, it is essential for the model to be able to both zoom in to focus on a small region and zoom out to grasp the full screen for screen summarization at the same time. The statistics of the three datasets can be found in the previous papers. We use the same dataset splits for comparison. Figure 2 shows an example of each task.

# 4 MODELS

Our models are designed based on the general encoder-decoder architecture that has been widely used for visual language modeling (Chen et al., 2022; Alayrac et al., 2022; Wang et al., 2022). We employ ViT, a popular choice, for encoding images (screenshots). In contrast to previous visual language models, there is an important difference in Spotlight. UI modeling tasks are often concerned with a specific region on the screen. This unique aspect of UI modeling requires a model to be able to concentrate on a specific region. To this end, we investigate two methods for realizing the Focus Region Extractor illustrated in Figure 1 that computes region representation.

Region-of-Interest (ROI) Pooling: ROI aligned is introduced previously for obtaining the feature map of a specific region on an image (He et al., 2017). This offers a parameter-free approach for average or max pooling the feature map of an image over a specific region. The method takes care of low spatial resolutions in the latent feature space using interpolation. In our work, the bounding box of an object is used to directly crop the ViT outputs (image encodings) corresponding to a target object, and the cropped encodings are then averaged spatially to result in a fixed-length vector for the object. This method provides a direct localization of the object in the encoded visual signals. The method embodies a soft cropping method as the resulted representation carries the information beyond the target area, including the contextual information on the screen. This is in contrast to hard cropping methods that crop the raw pixels of the target area and lose the access to the screen context.

Region Summarizer: Previous works have used random vectors as input in Transformer models to query into visual modalities for specific tasks. For example, DeTR (Carion et al., 2020) used random queries for retrieving visual objects on an image. Flamingo (Alayrac et al., 2022) summarizes image encodings by using random vectors to resample the image encodings. Inspired by these methods, we

propose to use the bounding box of an object as attention queries to the ViT outputs. During training, the models will learn to summarize a target region indicated by a bounding box query to focus on the object area. We hypothesize that the region summarizer, as a Transformer model, has the capacity to learn how to represent a specific region while taking into account of the screen context. As we will discuss later, our experiments show that Region Summarizer offers superior performance over the ROI pooling. The pseudo code of the Region Summarizer is shown in Listing 1.

We use an auto-regressive decoder to generate the text tokens. For the pretraining task, widget captioning and screen summary, it is straightforward that the decoder will attend to the regional screen representations and decode the captions or summaries auto-regressively. For command grounding, we treat it as a binary classification problem. Given a user command, we inspect each object on the screen by asking the model to predict either True or False, by appending either True or False to the end of the command prompt. Note that in this case only the last token is to be predicted and the command acts as a prefix and is encoded via self-attention in the decoder (see Figure 1).

# 4.1 PRETRAINING

During pretraining, we train the model to decode the text of an object, and the text is randomly sampled from the four text elements of an object: text, content description, resource id and OCR text. We found that the object text from view hierarchy contains very frequent words or phrases, e.g., submit and input password. To counter the imbalance, we subsample the frequent phrases as in word2vec (Mikolov et al., 2013) with  $t = 1e - 5$ . As we want to explore few-shot prompting in addition to finetuning, we sample a random number of examples  $n \in [1,5]$  and pad the input sequence to 5 examples, similar to Flamingo (Alayrac et al., 2022). The ViT encoder encodes each screenshot independently, while the decoder decodes the full sequence of the text of all the pairs, concatenated by  $BOC$  (Beginning of the chunk) and  $EOC$  (End of the chunk) tokens. In this way, we hope the model can generalize to use sequences of multiple screenshot-object pairs and potentially learn the few-shot prompting capacity for UI tasks as the previous work has shown for tasks in the general domain.

# 4.2 FINETUNING, MULTI-TASK LEARNING AND FEW-SHOT PROMPTING

We investigate three modeling strategies in our work. For finetuning, we finetune the pretrained model (Section 4.1) for each of the three UI tasks separately. We use one screenshot-object pair in each example for both finetuning training and evaluation. For multi-task learning, we finetune the

pretrained model (Section 4.1) for the three tasks simultaneously. We sample  $n = 2$  screenshot-object pairs for each example from each task during training. Therefore, during evaluation we can prompt the model with an screenshot-object pair from the training set of the target task, which the prompt acts as the task indicator. For few-shot prompting, we use the pretrained model directly for evaluation, i.e., no further change for the model parameters is needed. We experiment with  $n \in [0, 4, 8, 16, 32]$  shots to see if the model performance can improve as more example prompts or context are given. Note that we only need to vary the number of screenshot-object pairs in each example without modifying the model architecture for the three use cases.

# 6 DISCUSSIONS

Spotlight models advance the vision-only models for UI tasks by using a large-scale pretraining dataset and a general architecture that can support different use cases. As shown in Section 5, pretrained models significantly outperformed the models trained from scratch. There are various ways of how to use the unlabeled dataset to pretrain UI models (He et al., 2020; Bai et al., 2021). In our early exploration, in addition to pretraining the model to decode object text from view hierarchies, we experiment with decoding a serialized view hierarchy directly. However, this approach led to poor pretraining performance, likely due to the issue that the serialized view hierarchy contains a lot of noise (Li et al., 2022), which hinder the model performance. Nevertheless, the structural information buried in the view hierarchy is valuable and how to use it for better pretraining remains an interesting direction for future work.

The proposed vision-only models outperformed previous models using both images and view hierarchies as input. As previous models depend on the text information in the view hierarchy as input features, missing text can significantly affect their performance. We compare the performance of Spotlight with the benchmark model of the widget captioning task (Li et al., 2020b) on screens with a varying degree of missing text (Table 6). For this analysis, we sort all the screens in the test dataset based on the percentage of UI elements on the screen that have missing text, e.g.,  $10\%$  means the top  $10\%$  screens that have the highest missing text percentages, i.e., the least text availability, and  $50\%$  means the half of the test screens that have the most missing text. We can see that the Spotlight model performs stably across screens with missing text in their view hierarchies, because Spotlight does not use view hierarchy as input. However, the performance for the benchmark widget captioning model decreased significantly as the text information become less available in the view hierarchy, and view hierarchy text information serves as an important feature for the previous model.

Compared to the recent large vision-language model efforts (Alayrac et al., 2022; Chen et al., 2022) that use models of size  $O(10B)$  parameters, we have only investigated the use of a smaller versions of ViT and T5 components which have up to 843M parameters. Our experiments consistently show the trend that a larger model yields better performance, which promises that simply scaling up the model sizes would potentially lead to an even larger performance gain. Our model architecture is simple and can easily adopt larger ViT and T5 checkpoints. Our model architecture is generic, which takes a screenshot and a region of interest as well as text prompts, and outputs text responses. Our model can be easily applied to more UI tasks, e.g., icon classification (Deka et al., 2017), tappability prediction (Schoop et al., 2022) and multi-step grounding (Li et al., 2020a; Burns et al., 2022) as these tasks can be formulated as a text decoding task.

# 7 CONCLUSIONS

We presented Spotlight, a vision-only approach for mobile UI understanding, which alleviates the need to use view hierarchy. We design Spotlight based on a general vision-language model architecture and enable the model to focus on a region of interest on the screen. This architecture is easy to scale and can benefit from the success of existing large vision-language models pretrained for the general domain. Spotlight is able to fulfill a range of UI modeling tasks. We investigated various region representations and model sizes. We report our findings on a variety of modeling strategies and use cases, including finetuning, multi-tasking learning and few-shot prompting. Our experiments show that Spotlight obtains SoTA results on several representative UI tasks and outperforms previous works that use both screens and view hierarchies.
